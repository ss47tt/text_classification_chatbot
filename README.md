# Customer Service Agent — Bitext DeBERTa → Llama → SQL

A local, agentic customer-service chatbot built as a [LangGraph](https://github.com/langchain-ai/langgraph)
state machine. A fine-tuned DeBERTa classifier routes each customer message
by intent; simple requests get a direct conversational reply from a local
Llama model, while data-lookup requests are turned into SQL, validated,
executed against a SQLite database, and summarised back to the customer.

## Architecture

```
Customer message
      │
      ▼
┌─────────────────┐
│ classify_intent  │  DeBERTa (fine-tuned on Bitext, 27 intents)
└────────┬─────────┘
         │
   confidence < 0.5 ──────────────► handle_error ──► END
         │
   needs_sql? ──── no ────────────► generate_response ──► END
         │
        yes
         ▼
┌─────────────────┐
│  generate_sql    │  Llama writes a SELECT query against the DB schema
└────────┬─────────┘
         ▼
┌─────────────────┐
│  validate_sql    │  Blocks DROP / DELETE / TRUNCATE / ALTER / UPDATE / INSERT
└────────┬─────────┘
         ▼
┌─────────────────┐
│  execute_sql     │  Runs the query against customer_service.db
└────────┬─────────┘
         │
   error? ── yes, retries < 2 ─────► back to generate_sql
         │
        no / retries exhausted
         ▼
┌──────────────────┐
│ generate_response │  Llama summarises the SQL result (or apologises on error)
└────────┬──────────┘
         ▼
        END
```

## Repository structure

| File | Purpose |
|---|---|
| `deberta_bitext.py` | Fine-tunes `microsoft/deberta-v3-base` on the [Bitext customer-support dataset](https://huggingface.co/datasets/bitext/Bitext-customer-support-llm-chatbot-training-dataset) (27 intents). Saves the trained model to `./out/final_model`. |
| `init_db.py` | Creates and seeds `customer_service.db` — the SQLite database the agent queries for order/invoice/refund/payment/delivery lookups. Safe to re-run. |
| `agent_bitext.py` | The LangGraph agent itself: intent classification, routing, SQL generation/validation/execution, and response generation. Run this to chat with the agent. |
| `test_db.py` | Standalone sanity check for `customer_service.db` — prints the schema and runs one sample query per SQL intent, without loading DeBERTa or Llama. |
| `customer_service.db` | Generated by `init_db.py`. Not meant to be edited by hand. |

## Requirements

```bash
pip install langgraph langchain langchain-huggingface
pip install langchain-community sqlalchemy sqlparse
pip install langchain-ollama transformers torch
pip install datasets evaluate
```

You'll also need a local LLM runtime. Two options are wired into `agent_bitext.py`:

- **Option A — Ollama (recommended, CPU-friendly)**
  1. Install [Ollama](https://ollama.com)
  2. `ollama pull llama3.2:3b`
  3. Make sure the Ollama background service is running (`netstat -ano | findstr 11434` on Windows should show it `LISTENING`) before starting the agent.

- **Option B — HuggingFace `meta-llama/Llama-3.2-3B-Instruct` (needs a GPU)**
  1. `pip install accelerate bitsandbytes`
  2. `huggingface-cli login` and accept the Meta licence on the HF Hub
  3. In `agent_bitext.py`, swap the `llm = load_llama_ollama()` line for `llm = load_llama_huggingface()`

## Setup

Run these once, in order, from the project folder:

**1. Train the intent classifier**
```bash
python deberta_bitext.py
```
This downloads the Bitext dataset, fine-tunes DeBERTa for 3 epochs, evaluates on a held-out test split, and saves the model to `./out/final_model`. Update `DEBERTA_PATH` at the top of `agent_bitext.py` to point at that folder (it currently uses a hardcoded absolute path — adjust it to your machine).

**2. Create the database**
```bash
python init_db.py
```
Creates `customer_service.db` next to the script, with tables for customers, orders, order items, invoices, payments, refunds, refund policy, deliveries, delivery options, cancellation policy, and reviews — seeded with a handful of sample rows so SQL-routed intents return real data.

**3. Run the agent**
```bash
python agent_bitext.py
```
Chat at the `Customer:` prompt. Type `quit` to exit.

## Testing

**Database only (fast, no models needed)**
```bash
python test_db.py
```
Prints the full schema exactly as Llama sees it, then runs one representative query per SQL intent directly against `customer_service.db`, bypassing DeBERTa and Llama entirely. Use this first to isolate schema/data problems from model problems.

**End-to-end, through the running agent**

Once the database checks out on its own, run `python agent_bitext.py` and try one message per SQL intent to exercise the full classify → generate_sql → validate_sql → execute_sql → generate_response path:

| Intent | Try typing |
|---|---|
| `track_order` | "Where is my order?" |
| `check_invoice` / `get_invoice` | "Can I get a copy of my invoice?" |
| `check_refund_policy` | "What's your refund policy?" |
| `track_refund` | "What's the status of my refund?" |
| `check_payment_methods` | "What payment methods do you accept?" |
| `check_cancellation_fee` | "How much does it cost to cancel my order?" |
| `delivery_options` | "What delivery options do you offer?" |
| `delivery_period` | "How long will delivery take?" |
| `review` | "I want to leave a review for my order" |

Watch the console for the `[DeBERTa] Intent: ... | SQL: True` line to confirm routing picked the intent you expected, then `[Llama SQL]` and `[SQL Executor]` to see the generated query and its result.

## Intent taxonomy

The Bitext dataset defines 27 intents across 10 categories. This agent splits them into two routing groups:

**SQL intents** (need a database lookup): `track_order`, `check_invoice`, `get_invoice`, `check_refund_policy`, `track_refund`, `check_payment_methods`, `check_cancellation_fee`, `delivery_options`, `delivery_period`, `review`

**Chat intents** (handled conversationally, no DB lookup — e.g. because the request is *initiating* something with no existing record to query yet, like `get_refund`): `cancel_order`, `change_order`, `place_order`, `get_refund`, `payment_issue`, `complaint`, `contact_customer_service`, `contact_human_agent`, `create_account`, `delete_account`, `edit_account`, `recover_password`, `registration_problems`, `switch_account`, `change_shipping_address`, `set_up_shipping_address`, `newsletter_subscription`

Below 50% classifier confidence, the agent skips routing entirely and asks the customer to rephrase.

## Known limitations

- **No customer identity / query scoping.** `AgentState` has no authenticated `customer_id`, so Llama-generated SQL isn't scoped to "this customer's" data — a broad `SELECT * FROM orders` would return every customer's records. Fine for local testing against seed data; would need a fix (e.g. injecting and enforcing a `customer_id` filter server-side) before handling real, multi-customer data.
- **LLM-generated SQL, not templated.** `generate_sql` blocks destructive keywords (`DROP`, `DELETE`, etc.) but doesn't constrain *what* gets selected or from where, so it can still be steered by unusual phrasing in the customer's message (prompt injection).
- **`OUT_OF_SCOPE_INTENTS` is currently empty.** All 27 Bitext intents are legitimate in-scope categories, so nothing routes through the "politely decline" branch today. It's a hook for a future fallback label (e.g. a genuinely unrelated/unknown classification) rather than dead code to remove.
- **Ollama connection errors on first run.** If `agent_bitext.py` fails with `ConnectError: ... target machine actively refused it`, the Ollama background service likely wasn't up yet — confirm it's listening on `11434` and retry.
